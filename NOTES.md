# Небольшие комментарии по реализации

1. Я намеренно не захватываю лок в `diag_putc`, так как он вызывается только из-под уже захваченного `diag_lock` в `pr_msg`. Это связано с тем, что при взаимодействии с локом в `diag_putc` атомарным становился вывод лишь 1 байта, и во время тестирования иногда получалась "каша". В итоге `diag_lock` захватывается 1 раз в `pr_msg` и отпускается лишь после записи. Это гаранитрует атомарность целого сообщения.

2. Логирование управляется вызовом `logctl` с 2 аргументами: битовой маской классов событий и длительностью в тиках. Для удобства дублирую маски здесь:
```c
LOG_SYSCALL (1<<0) // Системные вызовы
LOG_IRQ (1<<1) // Аппаратные прерывания
LOG_PROC (1<<2) // Создание/завершение процессов
LOG_EXEC (1<<3) // exec
```
